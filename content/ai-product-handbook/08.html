    Kiến trúc hệ thống AI cho production

    Bốn lớp của một hệ thống AI production, model gateway với fallback khi nhà cung cấp lỗi, orchestration, hạ tầng cloud, và các chỉ số vận hành: TTFT, throughput, error rate, uptime.

      Ý chính của chươngĐưa AI từ prototype lên production là bài toán độ ổn định, latency, khả năng mở rộng và chi phí, không phải bài toán prompt.
      08.1

      Bốn lớp kiến trúc

      Frontend, orchestration, model, data và messaging: mỗi lớp lo một loại rủi ro.

      Tách lớp rõ giúp thay thế từng phần mà không đụng phần còn lại: đổi nhà cung cấp model chỉ chạm lớp model, đổi vector DB chỉ chạm lớp dữ liệu. Ví dụ dùng dịch vụ AWS vì báo cáo nguồn viết theo AWS; các cloud khác có dịch vụ tương đương.

      08.2

      Model gateway và orchestration

      Mọi lời gọi model đi qua một cổng chung, nơi quản lý key, rate limit và chuyển nhà cung cấp khi lỗi.

      Model gateway là lớp đệm quản lý mọi kết nối API tới model: giữ API key tập trung, load balancing, rate limiting. Khi gặp lỗi giới hạn tần suất (HTTP 429 Too Many Requests), hoặc nhà cung cấp chính chậm bất thường hay gián đoạn, gateway kích hoạt fallback: tự chuyển truy vấn từ nhà cung cấp chính sang nhà cung cấp phụ mà người dùng không bị gián đoạn.

      Orchestration dùng framework như LangChain, LlamaIndex, LangGraph hoặc dịch vụ như AWS Lambda, Step Functions để điều phối chuỗi tác vụ phức tạp, quản lý state và khôi phục khi có sự cố. Với agent nhiều bước, phần quản lý state và khả năng chạy lại từ bước lỗi quan trọng hơn chọn framework nào.

      Ghi nhớFallback giữa các nhà cung cấp chỉ an toàn khi bạn đã chấm model phụ trên cùng eval set với model chính.
      08.3

      API, database, queue và tích hợp

      Một sản phẩm AI trên cloud ghép nhiều dịch vụ: lưu trữ, suy luận, hàng chờ, phân quyền, kết nối riêng.

      Thành phầnVí dụ trên AWSVai trò
      Lưu trữ dữ liệuAmazon S3Tài liệu thô, dữ liệu huấn luyện, dữ liệu kiểm thử, log
      Suy luậnAmazon Bedrock / SageMaker AIGọi foundation model qua API (Bedrock) hoặc huấn luyện, fine-tune, triển khai model riêng (SageMaker AI)
      Hàng chờ, bất đồng bộAmazon SQS / EventBridgeĐệm request để kiểm soát rate limit khi gọi LLM, giảm tải backend
      Danh tính, phân quyềnAWS IAMPhân quyền giữa các dịch vụ, bảo vệ API key và tài nguyên
      Kết nối riêngAWS PrivateLinkDữ liệu giữa các dịch vụ AI không đi qua internet công cộng

      Hàng chờ là phần hay bị quên ở prototype. Khi lưu lượng tăng, gọi LLM đồng bộ trực tiếp từ request của người dùng dễ đụng rate limit; đẩy qua queue giúp hệ thống chịu tải đều hơn với các tác vụ không cần trả lời tức thì.

      08.4

      Observability, latency và mở rộng

      Bốn chỉ số vận hành cốt lõi, cộng với theo dõi token theo thời gian thực để không vỡ ngân sách.

      • Latency (TTFT): thời gian tới token đầu tiên.
      • Throughput: số token hoặc request xử lý được mỗi đơn vị thời gian (TPS, RPS).
      • Error rate: tỷ lệ lời gọi API thất bại hoặc bị ngắt.
      • Uptime: tỷ lệ thời gian hệ thống chạy không sự cố.

      Về chi phí, theo dõi lượng token tiêu thụ theo thời gian thực để không vượt ngân sách. Prompt caching cho các câu hỏi hoặc phần prompt lặp lại giúp trả kết quả nhanh mà không phải gọi lại model, vừa giảm chi phí vừa giảm latency. Observability tốt cho hệ thống AI còn gồm trace từng bước của agent: prompt nào đã gửi, công cụ nào đã gọi, kết quả nào quay về, để khi trả lời sai có thể lần ra bước hỏng.

      Ghi nhớKhông có trace thì không debug được agent. Ghi lại prompt, tool call và kết quả của từng bước.
